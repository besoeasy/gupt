# AGENTS.md

- **CSS**: custom CSS only — no Tailwind utilities. A component's rules live in its scoped `<style>`; `src/index.css` holds only genuinely global ones (tokens, resets). Classes migrated off Tailwind stay in `@layer gupt-components` so that file keeps overriding them; rules you write by hand stay unlayered.
- **Themes**: style every screen for light and dark with `--app-*`/`--ui-*` tokens (or `color-mix` with them), never hardcoded colours, and check both ways. A translucent tint used by two components becomes an `--app-*` token in `src/index.css` (opaque fallback, then `color-mix` in the shared `@supports` block). Light-mode corrections live in the owning component right after the rule they fix; only overrides several components share belong in `index.css`.
- **UI**: mobile-first and modern — no horizontal scroll, ≥44px touch targets, no hover-only interactions, and animate everything (fade-in on load, hover/touch feedback). No back button on routes that show the navbar; add one only where it is hidden.
- **Logos & avatars**: hand-written, self-contained SVG only — no logo packages, stock art, CDN/hotlinked images or external fonts; reuse the G-mark from `public/favicon.svg`, and give standalone files `role="img"` plus `<title>`, decorative inline copies `aria-hidden`. Faces come from `src/lib/avatar.js` (hashed grid, no dependency, no request — the seed is a pubkey); its algorithm is frozen and `test/avatars.test.js` pins it with digests.
- **Components**: PascalCase, one per file in `components/`; split at ~500 lines, when markup or logic repeats, or when a block owns state. Props instead of copy-pasted variants, complex logic in composables, and do not split simple one-off markup.
- **IndexedDB**: the cache is disposable — relays are the truth. Its database name derives from `STORE_SPECS` (`schemaFingerprintOf`), so never hardcode `gupt_cache_*`, read `STORE_SPECS` from app code, or write a migration/`DB_VERSION`: a layout change opens a fresh database and the old one is swept on boot. Unsent events live in the `gupt_outbox_v1` localStorage queue, never in IndexedDB only.
- **Version**: `package.json` `version` is the UTC release date alone, `YYYY.M.D` (`2026.11.20`) — unpadded, because semver forbids leading zeroes and `npm version` rewrites them — one release per day, no counter. `npm run release:bump` writes it into `package.json`, `package-lock.json` and the flatpak metainfo; `npm run release:check` is the gate; never hand-edit any of the three.
- **Support window: 400 days.** Every build must keep working against a client or relay up to 400 days old. The numbers live in `src/config/compat.js` and nowhere else (`test/compat.test.js` guards them); the remembered device stays at 3 days (`VAULT_TTL_MAX_MS`), so the window covers the secret+PIN path. Protocol integers (`RABTA_VERSION`, vault `v`, ciphertext `v`) never follow the calendar or the app version.
- **Breaking** (needs the whole window): event envelope (`v1`/`v`, sealed fields, blob parts), `RABTA_VERSION`, event `type`/tags, secret+PIN key and address derivation, `gupt_vault_v1`, `gupt_outbox_v1`, localStorage keys, relay `api_version`. Not breaking: the disposable `gupt_cache_*`. Readers must skip what they do not know — a new `type`, unknown payload field, newer ciphertext `v` — never throw.
- **Migrations**: deprecate in three steps — read both formats while writing the new one, note it in the release notes, then drop the old read path 400 days after the last build that wrote it. Every shim is dated: `// COMPAT: remove after YYYY-MM-DD — <old format + why>` in the same commit, deleted when the date passes; no permanent shim, no undated TODO. GUPT has not shipped yet, so never shim a pre-deploy shape.
- **Writer stamp**: `src/lib/writerVersion.js` stamps `w` (the release) onto vault records in `save()` and all event `data` in `finalizeEvent` — the only two write paths, and new stored shapes go through them. `w` is metadata, never a readability gate: readers accept on the protocol integers and use `isWrittenBefore()` only to pick a migration, which still needs its own dated tag.
- **Read-repair**: an older item is upgraded the moment a reader sees it, through the same write path that owns it, before the value is returned — copy `keyVault.open()`, `readOutboxBox()` and `loadPersisted()`. Never park an old shape for a batch job, a sweep or a future release. Repair drains what this device owns; signed relay events stay read-only until retention expires, so the `COMPAT` tag remains.
- **Storage keys**: keep a localStorage key stable and version its payload with `v` + `w` (`src/lib/storedMap.js` for map-shaped stores) — renaming a key to add a field throws the data away. Backfilling a missing field beside the existing write is not a migration. The app never renders the version: Settings shows `__APP_BUILD_TIME__`, and `__APP_VERSION__` only feeds the writer stamp.
